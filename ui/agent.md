# Driving the scanner as an AI agent

Your whole world is `engine.api`: the verbs listed in the README plus the dataclasses they return. The same verbs work in mock mode and on the real rig.

## Contract

- **Use the API only.** Never import `engine.capture.*`, `swiss_army_sensor`, `hid` or `cv2`, and never open or edit library files directly. The engine enforces the §9 safety rules, and bypassing it bypasses them.
- **Physical steps are human-only.** Placing or removing an object, focus, iris, gauge blocks and entering true dimensions are done by a person. Prompt the human, wait for them to confirm, then call `check_signal()` to verify the setup. Never assume the physical state. (In mock mode, `api.mock_bench().place(...)` / `.clear()` stand in for the human.)
- **Read numbers, not pictures.** Use `SignalReport.gc_conf` / `valid_pct` / `focus_hint`, `Dimensions.H/W/L` + `units` + `error`, and `Verdict.result`. Always check `units` and `warnings`: `px` means the result is uncalibrated (rule 6).
- **Never move the rig between base and object.** If the rig moved, capture a new base and recalibrate. The engine refuses to mix geometries.

## Typical flow

1. `load_preset(name)`. Read `preset.warnings` and `preset.calibration`.
2. Ask the human to clear the scene. Then `check_signal()` and repeat until `ok`. Relay `focus_hint`.
3. `capture_base(preset, "empty")`.
4. Ask the human to place the part, without touching the camera or projector. Then `capture_object(preset, base, label, known_dims=...)`, with known dims only if the human supplies them.
5. `measure(scan)`, or `calibrate(preset, [scans with known dims])` and then `measure`.
6. `compare(scan, golden)` for PASS/FAIL.

gc_conf bands: below 8 is unusable, about 18 marginal, about 30 usable, and 120+ excellent.

## From the command line

`scan.bat [--mock] [--json] <command>` (= `python -m ui.cli`). Add `--json` and read one JSON document: `ok`, `exit_code`, the result with its `units` and `warnings`, and `outputs_written`. Branch on the exit code:

- `0`: ok (PASS, signal ok, spot found, PRESENT, ALIGNED)
- `1`: not ok (FAIL / FLAG / INDETERMINATE, ABSENT, NOT_ALIGNED, base auto-rejected, cancelled)
- `2`: refused (rule, geometry, config or bad input; `RigBusy` means another program holds the rig, so wait or queue the job in the web UI; `PathTooLong` means the library, runs or output folder is too deep for Windows: the message names the path, its length and the limit - ask the human for a shorter `--library` folder or long paths, never retry it as it is)
- `3`: mode not built yet
- `5`: `measure-run`: NOT MEASURABLE - no number is given (read `reason` and `how_to_fix`; `0` = MEASURED: read `values[]`, each with `units`, `n_points`, `uncertainty` and `near_resolution_limit`; a measurement has no verdict: `result` is null and `disposition` is `"NONE"`)
- `5`: PULL (quality inspection) for `run`, `recipe-run`, `quick-check`, `face-check`, `station-check`, and for `face-locate` (the face reads the wrong size) and `face-scan` (no camera exposure fits this seating: nothing was scanned): the result is in doubt (INVALID, INCOMPLETE, a guard band, an unreadable code, a size mismatch); never read it as a pass or a reject (`disposition`, `pull_reasons`: at the top level of the `--json` output of these five commands, also when they were refused or crashed)

Operating modes: `measure-run PRESET --what flatness|step|distance|cylinder|endface|dims|deviation [--roi X0,Y0,X1,Y1] [--repeats N]` measures and reports (never judges); `quick-check PRESET --check flatness|golden|recipe --threshold MM` runs ONE check (exit 0 CONTINUE, 1 REJECT, 5 PULL); `run <station config>` runs a station's work states. A preset with `rig.mount` `mobile` (or at the geometry of one) gives no mm until the rig was verified in this session: `rig-session` says so; `rig-check` OK at the default tolerance against the reference stored while the rig was verified (a human puts the rig on its reference scene first), or a calibration from poses captured now, verifies it. Storing a new reference (`rig-check --set-reference`) on a rig in doubt verifies nothing; `scan-metric` / `scan-fast` are refused (2) meanwhile. A FIXED rig whose `rig-check` said MOVED / UNKNOWN still scans, but the JSON says `rig.trusted` false and `warnings[0]` starts "fixed rig not confirmed": report those mm as unconfirmed, with the warning. `rig-check` MOVED names the device in `moved` (camera / projector / camera and projector / camera or projector): only a camera move can be re-homed (`rig-check --rehome`); for a projector move ask the human to put it back, else recalibrate. A scan warning "the calibration may not fit this rig any more" means: run `rig-check` before trusting its mm. Never present a NOT MEASURABLE or a PULL as a number or a pass.

Zone flow: `map` (once per rig position) → `grid` → read the grid photo named in `camera_png` and find the cells the part covers → `scan part --zone H8:I11@96`. Keep the `@96`: it pins the cell names to the grid in that photo.

Painted zones (README, *Zones: paint them on the part*): on the real rig a HUMAN draws them on the part with the projected mouse cursor (`zone-paint --name SET`; it holds the rig until Space / Esc - never start it and wait as an agent; `--mock` replays `--events FILE.json | demo`). Use what was painted: `zones` (the sets; `zones SET --recipe` prints recipe zones), `zone-show SET` (exit 0 every zone lands in the camera image; read `zone_show.zones[]`: `seen`, `centroid_px`, `bbox_px`), `scan-fast LABEL --zones SET[:Z1,Z3]` (only those zones are lit; `zones.counts` = points per zone, `null` = unknown, never 0), `measure-run P --what flatness --zones SET:Z1`. A set is bound to the rig geometry it was painted at: exit 2 (GeometryMismatch) means it must be painted again with this preset, not that it can be reused. Several sets at once: `--zones a --zones b:Z1` (or `a+b:Z1`); zones are then named `<set>/<id>` (`cells/Z1`) and measured / judged one by one - flatness is one plane PER ZONE (`values[].zone`, names like `cells/Z1:flatness_rms`), a quick check applies its limit to each zone (`zone_selection.by_zone[]`: `verdict`, `max_mm`, `points`, `coverage_pct`; `zone_selection.failed` names the zones over the limit). The zone selection is which sets are switched on at this rig placement (the operator page's Scan zones panel shows the same): `zone-select` prints it (exit 1: it names something gone - read `selection.problems`), `zone-select SET[:IDS] ...` / `--on` / `--off` / `--clear` change it, `--zones selection` uses it. A selection that cannot be resolved is never replaced by the whole field: exit 5, NOT_MEASURABLE / INVALID → PULL, with the reason. A station run uses the selection only when its configuration's job says `"zone": "selection"`.

Virtual sensors: `spot-size 6.5 [--measured K]`, `spot H8 --diameter 6.5`, `teach-presence pe H8 --diameter 6.5 --empty-confirmed` (pass the flag only after the human confirms that the sensor's field is empty), `check-presence pe` (exit 0 PRESENT), `teach-align fixture <scan>`, `check-align fixture <scan>` (exit 0 ALIGNED), `sensors`. Positions: a cell `H8`, `dmd:COL,ROW` or `cam:X,Y`.

Cylinders and 3D (on a stored scan): `mesh <scan> --kind relief|base|cylinder --fmt stl|obj`, `unwrap <scan> --radius 24.05` (seen arc, end-face height, dent heatmap), `dents <scan>` (exit 0 PASS; 1 FAIL or INDETERMINATE: uncalibrated px never passes, and only the seen open arc is inspected), `maps <scan> [--spectral ID --light ID --golden ID]`, `checker`. Read `units` first: `px` means no mm (rule 6).

Dents on shiny cylinders (needs a stereo calibration at the geometry): the human places a KNOWN-GOOD part, then `--preset DARK dent-scan good1 --zone H9:I12 --short-preset SHORT` and `dent-null good1 --diameter 21.05`; per cell `dent-scan cellN ...` and `dent-detect cellN` (exit 0 CLEAR, 1 FLAG, 4 the detector itself failed: never read 4 as a verdict; the diameter comes from the matching null). Read each candidate's `level` (detection above 1.25 x the good part's maximum / watch / edge), `kind` (dent / scratch / speck, advisory), `depth_mm` with `depth_reliable` and `depth_significant`, and its place on the cylinder (`theta_deg`, `s_from_top_mm`; `s_mm` is from the axis point level with the camera, not a cylinder end). The null calibration is per cylinder diameter, fixture, pattern set and stereo calibration: recalibrate on a good part when any of them changes (a null made with `--fixture NAME` needs `dent-detect --fixture NAME`). Read the report's `warnings` (e.g. a finder excluded by the null, no mirrored room line on this cell).

End faces (a cylinder lying with its circular END FACE toward the camera; needs a stereo calibration): the human places the part, then `face-locate --zone H10:I12 --diameter D` (`--outer-diameter` = the part's outer diameter when the rim around the flat returns depth points; else read `meta.silhouette_diameter_mm`: found from the rim when it shows) (a ray-plane locate scan of the zone that keeps its flood pair - repeated at a longer / shorter frame-locked exposure when the located face is dark / clipped, the scans then merged per pixel (`meta.locate_scan.scans` / `notes`) - then the face: plane, rim circle of the known `--diameter` = the diameter of the bright flat the flood shows, camera -> DMD affine; read `affine.rms_col_px` / `rms_row_px`, a warning above 0.5 DMD px; read `meta.size_check`: the flood outline vs `--diameter`, more than 4 % off (`--size-tol`) is exit 5 with `disposition` PULL / `pull_reasons` `size_mismatch` - "part reads N % small: calibration or lens suspect": run `rig-check` / recalibrate, never rescale) (`face-locate <metric scan>` needs x AND y decoded: `scan-fast --axis xy` or `scan-metric`; an x-only scan is refused; `--auto-intensity` needs a preset with projection.invert false, e.g. a `*_bright` preset), `face-aim --check` (exit 0 ON_FACE; 1 OFF means the part moved: re-locate), `face-scan cN` (only the face lit, 3 repeats + polar set, at a frame-locked camera exposure chosen for this seating: auto exposure is the default when the preset's exposure is whole video frames - face flood p95 near 170 DN with < 0.5 % clipped, 16.7-100 ms, read `meta.exposure_us` / `exposure_source` / `auto_exposure.shots`; exit 5 with `auto_exposure` in the JSON and NO scan when none fits: the part must be re-seated; `--exposure-us N` forces one, `--no-auto-exposure` keeps the preset's; `--auto-intensity` tunes the duty first: it is for this scan only, the LED currents are never touched; `meta.low_repeats` / a warning "repeat N (...) kept M face points, far fewer than the other repeats" names a repeat something disturbed: scan again before trusting the face), `face-profile cN` (flatness inside 0.855 x the face radius, repeatability, `stats.repeats_used` of `n_repeats`, `repeat_face_points`, `all_repeats_pct` and `low_repeats` (what each repeat gave the profile), `radial`, `stats.rim_outline` (the flood outline: diameter, roundness rms / max), `stats.size_check` and `stats.centre` (the face frame is centred on the flood outline of the flat when the whole outline shows: `source`, and `located_offset_mm` = how far the located circle was from it; a warning above 0.035 x the face radius means: locate again, with `--outer-diameter`), PNG / CSV / STL). A golden needs several GOOD placements: `face-golden good1 good2 good3 good4` (default detector `mf_fir`: MF-CFAR + the reflectance FIR from the flood pair; every radius derives from the face diameter - `params.radii`: inspect 0.926 R, rim 0.855 R; `--inspect-r` / `--rim-r` set them, one rim radius for every detector; read `leave_one_out` - any trigger on a good placement is a false trigger - `sensitivity.by_size`, the synthetic-dent detection per depth x width, and `meta.rim_outline`, the outline's per-angle model; a placement that reads the wrong size is refused). Per cell `face-check cN` (exit 0 PASS, 1 FAIL, 5 PULL for quality inspection: INCOMPLETE - less than 90 % of the face measured is never passed - a size mismatch (`stats.size_check`: no verdict of a mis-scaled scan is trusted, not its FAIL either) a rim outline in its guard band or not judged all the way round (`stats.rim_outline.status` `incomplete`, `unjudged[]`: rim with no edge - a glint on the rim, a chip too deep to leave an edge, an outline that shows only in part), or a profile off its outline's centre (`stats.centre_check`: run `face-profile` again); `disposition` / `pull_reasons` in the JSON, also at its top level): each trigger has `zone` face | rim | rim_outline, `r_mm`, `theta_deg` (0 = camera right, 90 = camera down), `depth_mm` = `depth_centre_mm` (THE dent depth: the 3 x 3 grid-cell average at its deepest place vs the local background, positive = a dent; `--min-depth` applies to it), `depth_min_mm` (the single deepest point: over-reads), `width_half_depth_mm` (reads about one camera px wide), `depth_fit_mm` / `width_mm` (the matched filter's), `z` (significance; trigger at 5.5), `dev_mm` (negative = below the golden) and `area_mm2`; a `rim_outline` trigger is an edge dent: the flood outline moved in (`kind` notch, `depth_mm` positive; `at_least` true = the chip is deeper than the edge search reaches, the depth is a lower bound) or out (bulge) by more than 0.4 mm over `arc_mm` >= 1.5 mm of rim (`--rim-tol`, `--rim-arc`; `stats.rim_outline` has its rms / max; wide dents up to about 40 % of the rim read their depth, wider ones only the size check holds); `stats.noise_floor_mm` is the 1-sigma dent depth per width. Warnings about a saturated flood mean: re-scan (auto exposure keeps the face below clipping; `--auto-intensity` lowers the duty). `--detector band` uses the prototype band instead. `face-aim --hold 30` keeps the ring up as the human's placement guide. `faces` lists targets, scans and goldens.

Surfer atlas: `atlas-import <path.json> <name>` (the source is only read), `atlases`, then use a region anywhere a zone goes: `scan part --zone atlas:part/part`, `flood atlas:part/part`, `antiglare atlas:part/part` (a pattern choice, not wavefront shaping), `multiorient atlas:part/part`. `flash-pack --axes x` only writes files. A human switches the DLPC350 into pattern mode (docs/FLASH_PATTERN_MODE.md). Fast scan without a trigger cable: `fastscan-pack` (files only), a human loads it with the 4500 MKII GUI's firmware link and plays it, then `scan-flash <label> --pack DIR [--roi X0,Y0,X1,Y1]` records with the camera only and sorts the frames in software (exit 2 with the reason when the loop is not playing or not in order; `--dry-run` = the timing plan; `sort-flash <recording.npz>` re-sorts offline; docs/FLASH_SOFTSYNC.md). Never ask the engine to start or stop the sequence: it cannot.

Recipes (what the DLP checks to verify a work state; recipes/README.md): `recipe-list` (built-in + user, with preset, zones, checks), `recipe-checks` (every check type with its parameters and units), `recipe-validate NAME|FILE` (exit 2 lists every problem; validate before running), `recipe-golden NAME` (a human places a GOOD part first), `recipe-run NAME [--operator-confirmed]` (exit 0 CONTINUE, 1 REJECT, 5 PULL for quality inspection, 2 refused, 4 crashed). Read `result.disposition` (CONTINUE / REJECT / PULL) and `result.pull_reasons` ([{zone, check, reason, message}]): PULL is any doubt (INVALID, a crashed check, an unreadable code, ABORTED, a PASS within the recipe's `pull.guard_band_pct` of a limit) and is never a pass or a reject. Read `result.zones[]`: each zone's `verdict` and its `checks[]` with `values` (units in the names: `_mm`, `_deg`, `_mm2`, `_pct`), `limit`, `message` and `fault_points` (camera px). INVALID is never a pass: read `invalid_reason` (no stereo calibration, no golden, a zone with too few points). `feedback.rendered` says whether the verdict was painted on the part (`feedback.refused` says why not). `recipe-run NAME --scan ID --no-feedback` re-checks a stored scan without the rig, for tuning tolerances. Never write or edit recipe files in the repo's recipes/ (read-only); `recipe-add NAME --from BASE --set key=value` makes a user copy.

Station configuration, profiles, work states (stations/README.md): a station configuration (`stations/*.json`) is the station's parameters + its profile library set (one profile per part variant: long tube / short tube); it is NOT a work state. The work states are the steps of its flow: what the line's sensors claim (`expects`), the DLP check that confirms or corrects it (`verify`), the permission it grants (`permit`). `flow-show CONFIG` prints and validates (exit 2 lists every problem; validate before running). `run CONFIG [--profile NAME] [--input SIGNAL=true|false ...] [--operator-confirmed]` walks one whole cycle in line (exit 0 CONTINUE, 1 REJECT, 5 PULL, 2 refused); MOCK: `--mock-case NAME`. Read `result.steps[]`: each work state's `outcome` (CONFIRMED / CORRECTED / NOT_MET / DEFECT / DOUBT; PENDING = never reached), `sensor_inputs` vs `dlp_result.observed` (CORRECTED = they disagree: `sensor_mismatch`), `permission_granted`, `actions` and `message`; `result.permissions` is what the line may still do; `result.disposition` is CONTINUE only when every required work state was CONFIRMED. A prompt nobody acknowledges ends an unattended cycle PULL: never pass `--acknowledge` for a physical step you did not see a human do. A work state that expects a signal nobody reported is a DOUBT, never a pass: do not invent sensor claims. A claim belongs to one cycle (forgotten when it ends): report the sensors for every part, and act only on what follows a command the bus accepted (a refused START / TRIGGER scanned nothing and releases the last cycle's permissions and PASS). Over HTTP the same cycle is walked step by step: `POST /api/io/inputs {"part_present": true}`, `/api/cmd/start`, `/api/cmd/step`, `/api/cmd/ack`, `/api/cmd/profile {"profile": NAME}`, `GET /api/cmd/state` (`cycle.steps`, `prompt`, `permissions`, `signals.PERMIT_<NAME>`); verbs `flow_verify` (one work state's DLP check, grants nothing) and `flow_run` (a whole cycle).

Bad parts (README, *Bad parts*): a part judged REJECT or PULL is never a reference. Making a golden, a bank member, an alignment reference or a dent null from it is refused, and so is a check against a reference made from one (exit 2, `BadPartReference`: the message names the inspection and its reason; inside a run: PULL). Never work around it: ask the human for a good part (one that passed, or that no check has judged) and make the reference again. `run`, `recipe-run` and `quick-check` take `--bad-part-output DIR` (or `off`; else the configuration's `bad_part_output`, else `$SAS_BAD_PART_OUTPUT`): each REJECT / PULL is copied there. A warning that starts "bad-part output" means a copy failed or waits; it never changes the judgment or the exit code.

Library: `bases`, `scans`, `calibrations`, `readings`, `materials`, `banks`, `maps`, `sensors`, `faces`, `outputs`. `delete <id> --yes` moves an entry to trash/; nothing is destroyed. `scan.bat --help` lists everything.
