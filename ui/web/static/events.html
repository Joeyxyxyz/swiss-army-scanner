Every inspection that opened a run folder adds one row: a recipe run, a quick check, a station cycle (one row for the whole cycle), a measurement. A START that is refused before a run folder exists is not listed. Judgment: PASS, FAIL (disposition REJECT), or PULL (the part is pulled for quality inspection: the Reason says why); a measurement has none. Part ID is the code read from the part, when one was read. Under the Program: how the scanner was used (Measure, Quick check, Station, Recipe run); MOCK marks a simulated inspection. Times are the scanner's local time as the file holds them (with their offset to UTC); the files are kept by that month. The files are in the library folder under events/ and open in a spreadsheet program.

This page reads the whole month: late in a busy month that is many thousands of rows and can take a few seconds. When something happens to an inspection after its result was written (ABORT pressed after the verdict), its row is written again in the file; this page shows the last one, and in a spreadsheet the last row of an Inspection no. is the one that counts. A cycle that never ended (the program was closed while it ran) is listed as PULL after the log was rebuilt (python -m engine.eventlog --rebuild).
